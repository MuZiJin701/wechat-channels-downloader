# Spec：单条动态完整归档与跨平台终端体验

状态：需求已于 2026-10-21 获用户整体确认，代码已实现，本机自动检查通过；跨平台与人工验收的实际范围见[验证记录](validation.md)。本规格扩展[初版 Spec #1](https://github.com/MuZiJin701/wechat-channels-downloader/issues/1)，以已有可运行的便携式 TUI 为基础，不重新实现登录工具。

## Problem Statement

用户已经能够输入视频号分享链接并下载视频或图文，但现有输出只包含主视频或图文图片以及 TXT 正文。接口返回的独立封面、头像、认证图标、背景音乐、其他视频版本及发布信息没有完整保存；随机目录和通用文件名不便识别内容。仅保存媒体地址也不能保证以后仍能访问。

目前任一媒体下载失败会清理本次临时目录，用户无法保留已经取得的部分内容。用户需要明确区分完整归档、部分归档、失败和主动中断，并保护以前下载好的文件。

用户还希望在 Windows、Linux、macOS 上通过终端运行和图形界面双击使用同一 TUI：Windows 双击优先使用 Windows Terminal，界面配色跟随所在终端；便携包只提供必要使用文档，启动入口使用英文名称。

## Solution

对分享链接对应的一条视频号动态，沿用本机元宝登录态解析链路，保存两步解析的完整响应，并下载接口明确提供的全部已知媒体资源：视频、图文图片、封面、作者头像、认证图标和背景音乐。不同视频版本全部保存，完全相同的地址只下载一次。保持媒体实际格式和图文顺序，不转码或生成识别笔记。

每次下载创建一个动态归档：使用作者和正文摘要命名的目录、独立媒体、一份可双击查看的离线 HTML 和两份完整 JSON。HTML 保留原正文，整理作者、时间、互动展示数量及可理解的发布信息，并引用本地图片、视频和音乐；不生成 TXT。

部分资源失败后继续处理其他资源，保留成功文件和已取得的信息，在界面及 HTML 中如实报告结果。再次下载建立新目录，不覆盖旧归档。

已有终端运行时直接复用当前终端；图形界面双击时打开终端并进入 TUI。Windows 优先 Windows Terminal，不可用时回退系统控制台。主界面跟随终端配色，二维码区域保持黑白。分发包顶层只保留 README.md 和 README.en.md 两份使用文档，许可声明置于内部目录。

沿用已确定的平台目标：Windows 11 x64、Ubuntu 24.04 x64、macOS 14+ Intel 与 Apple Silicon。保留现有元宝登录态复用、必要时扫码、随包 Chromium 和便携数据位置约定。

## User Stories

1. 作为下载用户，我希望输入一条视频号分享链接，以便归档该链接对应的一条动态。
2. 作为视频型动态下载用户，我希望下载接口提供的视频文件，以便离线观看。
3. 作为视频型动态下载用户，我希望保存接口返回的所有不同视频版本，以便完整保留可取得的版本。
4. 作为视频型动态下载用户，我希望不同版本名称标明编码，以便选择播放器兼容的版本。
5. 作为下载用户，我希望完全相同的地址只下载一次，以便避免重复传输和占用空间。
6. 作为图文动态下载用户，我希望保存全部正文图片，以便不遗漏内容。
7. 作为图文动态下载用户，我希望保留图片顺序，以便按原有次序阅读。
8. 作为下载用户，我希望媒体保持实际返回格式，以便保留下载内容。
9. 作为下载用户，我希望独立封面一并保存，以便保留动态展示信息。
10. 作为下载用户，我希望作者头像一并保存，以便离线识别发布者。
11. 作为下载用户，我希望非空的作者认证图标一并保存，以便保留接口提供的作者展示信息。
12. 作为下载用户，我希望背景音乐有独立地址时能够下载，以便保留动态的音频资源。
13. 作为下载用户，我希望接口没有提供的可选项目自然省略，以便正常归档缺少头像、音乐或封面的动态。
14. 作为阅读用户，我希望正文原样保留，以便避免整理过程改写原意。
15. 作为阅读用户，我希望正文为空时仍可查看已有媒体，以便阅读纯媒体动态。
16. 作为阅读用户，我希望看到作者和可取得的发布信息，以便理解内容来源。
17. 作为阅读用户，我希望日期展示注明时区，以便正确理解发布时间。
18. 作为阅读用户，我希望保留接口当次返回的互动展示数量，以便了解归档时的信息。
19. 作为阅读用户，我希望数量被标明为当次展示值，以便不误认为实时或精确统计。
20. 作为阅读用户，我希望返回了位置或跳转文案时能查看这些文字，以便保留附加发布信息。
21. 作为归档用户，我希望分别保留元宝响应和视频号响应的完整 JSON，以便不遗漏任一步独有的字段。
22. 作为归档用户，我希望未知字段仍按原名保留，以便后续查看原始信息。
23. 作为阅读用户，我希望双击 HTML 即可查看整理结果，以便无需安装额外阅读工具。
24. 作为阅读用户，我希望 HTML 可以显示本地图片并播放本地视频和音乐，以便集中查看动态归档。
25. 作为阅读用户，我希望展示页使用本地媒体，以便远端地址失效后仍可查看。
26. 作为下载用户，我希望不再生成 TXT，以便减少零散的正文文件。
27. 作为下载用户，我希望目录用作者和正文摘要命名，以便从名称识别动态。
28. 作为下载用户，我希望原作者和正文中的中文可用于下载命名，以便保留原始辨识信息。
29. 作为下载用户，我希望媒体沿用动态名称并标明用途或顺序，以便识别散落的媒体文件。
30. 作为下载用户，我希望缺作者时省略作者、缺正文时使用分享标识，以便缺少信息也能正常命名。
31. 作为跨平台用户，我希望非法字符和过长名称得到处理，以便在目标文件系统中保存。
32. 作为下载用户，我希望名称截短后正文全文仍保留，以便不丢失内容。
33. 作为下载用户，我希望重复下载新建带序号的目录，以便保留旧版本。
34. 作为下载用户，我希望单项资源失败后继续处理其他资源，以便尽量取得可保存的内容。
35. 作为下载用户，我希望部分失败时保留成功文件及已取得的信息，以便不重复丢失下载成果。
36. 作为下载用户，我希望界面与 HTML 列明失败项并显示部分完成，以便知道归档缺少什么。
37. 作为下载用户，我希望全部媒体失败时仍保留已取得的信息并报告失败，以便查看可用线索。
38. 作为下载用户，我希望正常中断后保留已完成文件并标记已中断，以便知道结果尚不完整。
39. 作为下载用户，我希望不完整文件不被当成有效媒体，以便避免误用损坏内容。
40. 作为便携版用户，我希望目录不可写或保存失败时得到明确错误，以便调整程序位置或存储空间。
41. 作为下载用户，我希望失败、中断和重复下载不损坏以前的完整文件，以便保护已有归档。
42. 作为终端用户，我希望在当前终端直接运行 TUI，以便保留自己的终端环境。
43. 作为 Windows 用户，我希望双击英文名称的可执行入口即可打开 TUI，以便使用图形界面启动。
44. 作为 Windows 用户，我希望双击时优先使用 Windows Terminal，以便使用熟悉的终端。
45. 作为 Windows 用户，我希望 Windows Terminal 不可用时回退系统控制台，以便仍可运行。
46. 作为 Windows 用户，我希望已有终端中的启动不另开窗口或更改系统默认设置，以便保留当前工作环境。
47. 作为 macOS 用户，我希望双击英文名称的 command 入口打开 TUI，以便无需输入启动命令。
48. 作为 Ubuntu 桌面用户，我希望双击英文名称的 desktop 入口打开 TUI，以便从文件管理器使用工具。
49. 作为跨平台用户，我希望两种启动方式进入相同 TUI 并使用相同数据位置，以便获得一致体验。
50. 作为浅色或自定义主题终端用户，我希望背景、文字和主要配色跟随终端，以便避免强制黑色界面。
51. 作为终端用户，我希望按钮、输入框和错误信息仍清晰可辨，以便完成操作。
52. 作为扫码用户，我希望二维码保持清晰黑白，以便可靠扫码。
53. 作为终端用户，我希望正常退出后恢复原有终端属性，以便继续使用终端。
54. 作为便携版用户，我希望包顶层只有中英文两份 README 使用文档，以便快速找到说明。
55. 作为分发维护者，我希望第三方许可仍在包内保留，以便满足依赖的分发要求。
56. 作为便携版用户，我希望使用说明中的链接可用，以便避免打开不存在的包内开发文档。
57. 作为已登录用户，我希望继续复用有效元宝登录态，以便不因新功能反复扫码。
58. 作为便携版用户，我希望继续使用包内 Chromium 和程序旁的数据位置，以便无需新增系统运行环境。
59. 作为账户持有人，我希望凭据和带访问参数的地址不出现在公共日志或分发包中，以便保护本地会话和归档。
60. 作为维护者，我希望验收报告区分模拟流程、真实下载、离线播放和桌面双击，以便明确实际通过范围。

## Implementation Decisions

- 基于现有 Python 3.11、uv 锁定环境、Textual TUI、Playwright/Chromium 和 HTTP 下载流程实现，复用已有模块与依赖；没有新增技术栈或登录系统的需求。
- 元宝登录态检查、扫码、身份确认、有效状态复用及网络失败不误删旧状态的行为继续适用。本机先解析分享链接，再取得视频号动态信息，不要求远程解析服务。
- 在现有会话与下载编排中分别保留两步完整响应，从全部已知媒体字段收集候选资源。两步独有信息均需保留；缺失的可选字段自然省略，未知字段不进行猜测性解释。
- 视频型动态与图文动态均需完整处理。下载不同视频编码或版本、全部图文图片、独立封面、作者头像、认证图标和背景音乐，完全相同的地址只传输和保存一次，并让归档中的相关展示引用同一有效文件。
- 媒体保持实际响应格式，不通过扩展名猜测内容，不转码。验证目标地址、重定向、媒体类型和完整性；对样本中 HTTP 音乐地址可核验同地址 HTTPS，不能把已有安全校验整体放宽为任意域名或明文请求。
- 扩展现有下载结果与 TUI 状态的表达，能够区分保存位置、已完成资源及失败或中断结果；不把部分完成、失败或中断显示为全部成功。内部数据结构不在本规格中预设。
- 在归档输出中生成离线展示页，展示正文、作者、可取得的时间和互动信息以及本地媒体。正文只作安全展示处理，不改写；正文摘要仅为从原文截取的短文本。时间转换注明时区，互动展示字符串按原值保留。
- 两份 JSON 保存各步返回的完整字段，不附加请求 Cookie 或登录凭据。含时效参数的原始响应只保存在本地，不输出到公共日志、公共仓库或分发产物；展示页不依赖这些远端地址。
- 媒体、JSON 和展示页形成同一条动态归档；不再生成 TXT。外部文本、字段名和地址不得成为可执行脚本、目录穿越或任意文件写入来源。
- 下载目录采用作者与正文摘要，媒体沿用此前缀并附用途、序号或编码。缺作者时省略，缺正文时回退分享标识，清理非法字符及截短过长名称；保留全文，避免名称清理导致覆盖。
- 每次运行创建新归档目录，名称冲突附加序号，不合并、覆盖、删除或迁移旧归档。正常完成的文件与未完成内容应可区分，不因某项失败删除其他已完成文件。
- 继续处理单项失败后剩余的资源。全部计划资源及归档信息保存成功时报告完成；部分资源失败时保留成果并报告部分完成、在展示页列明失败项；全部媒体失败时保留已取得的信息并报告失败；正常中断时保留已完成文件和可保存的信息、标记已中断。保存本身不可执行时明确报错，不承诺已保存。
- 启动入口和打包逻辑继续按平台分别处理。终端直接运行复用当前终端；Windows 双击优先 Windows Terminal，缺失时回退系统控制台，不安装终端、不修改系统默认设置。两种入口进入同一个 TUI，实际程序和英文命名入口分别适配各平台。
- macOS 使用 command 双击入口，Ubuntu 桌面使用 desktop 双击入口；允许系统首次信任或允许启动提示。支持目标仍为 Windows 11 x64、Ubuntu 24.04 x64、macOS 14+ 的 Intel 与 Apple Silicon，不以单个平台构建推断其他平台可用。
- 界面适配所在终端的背景、前景及主要配色，包括浅色主题，保持交互和错误可辨识；二维码区域继续黑白显示。退出后在浏览器子进程清理完成时恢复原终端属性。
- 沿用便携存储决策：登录态和下载内容分开保存在程序旁，macOS 应用包场景存于包外侧，位置不随工作目录变化。不可写时明确报错，不静默迁移到系统用户目录。
- 调整分发内容，只在顶层提供中英文两份 README 使用文档；第三方许可及声明放内部目录，开发文档和代理约定不随包分发。同步中英文说明及链接，保留 Chromium、应用依赖和必要许可。
- 不预建新的模块层级、下载选项系统、通用归档框架或跨账户能力；保持现有完整用户流程和模块边界，按本需求调整会话下载、归档输出、TUI 状态、启动入口和打包职责。

## Testing Decisions

- 测试边界沿用用户已明确确认的一个最高业务边界：从 TUI 的登录态检查或扫码提示、链接输入，到两步解析、资源保存、离线展示及可见结果。用户已对包含这些验证要求的整体规格确认，本次不新增访谈或下沉为大量内部函数测试。
- 覆盖现有 TUI 编排、真实 Playwright/Chromium、元宝登录态持久化、解析和下载、归档生成；仅模拟元宝、视频号与媒体等外部服务，使用临时目录，隔离外网，不加载真实凭据。
- 好的测试观察用户可见状态、实际保存的文件内容、资源顺序、目录命名、两份响应和 HTML 的本地引用；不固定内部调用次数、私有状态、辅助函数名称或未来的模块拆分。
- 既有 TUI 工作流测试已经通过键盘提交链接，验证视频、图文、扫码复用、网络与认证错误、无正文及失败保护；在同一入口扩展全部媒体类别、多个视频版本、相同地址复用、两步独有字段和缺失字段，不重新建立解析器单测体系。
- 从完整用户流程验证命名回退、中文和非法字符、超长名称、名称冲突及重复下载，断言以前归档和登录态没有被覆盖。
- 从同一流程模拟单项失败、全部失败、返回非媒体、短文件、不可写目录和正常中断；断言成功内容保留、不完整文件不被当作有效媒体、其余资源继续处理，以及状态和展示页中的失败项准确。
- 对由 TUI 实际生成的 HTML 使用现有浏览器能力检查原文和本地媒体引用、失败展示及外部文本的安全处理，并阻断非预期远端请求。格式检查不等同于真实媒体解码或离线播放验收。
- 沿用已有构建命令保护与实际产物离线 smoke 检查，检查双 README、内部许可、开发文档缺席、英文启动入口，以及产物不含个人登录态和动态归档。
- Windows 验证已有终端直接运行、双击优先 Windows Terminal 和不可用时回退；macOS/Ubuntu 验证对应双击入口和终端运行。深浅及自定义终端主题、二维码可读性、真实文件管理器双击需要目标桌面环境的验收，不能只靠源码断言宣称通过。
- Linux/macOS 继续复用现有源码入口与打包产物的真实 PTY 检查，验证 Chromium 启动、正常退出和原终端属性恢复；Windows 明确跳过 POSIX 专属检查，不将跳过记录为平台通过。
- 实现阶段运行项目类型检查、完整测试和各平台构建/产物检查。Windows 本机验证，Linux/macOS 沿用现有 CI 架构；记录实际系统版本、架构及跳过项，较新 Intel macOS 的通过不能替代最低目标版本。
- 人工验收单独覆盖真实扫码与复用、至少一条视频型动态和一条图文动态、可取得的附属资源完整下载、离线播放以及两种启动方式。既有测试结果和资源首部读取不作为本规格的新验收结果。

## Out of Scope

- 发布者账号全量历史、批量队列、直播录制、非视频号站点和任意小程序链接。
- 接口未返回且本链路未证实能取得的评论正文、评论或点赞者名单、独立字幕、上传前原片、完整位置数据和创作者后台数据。
- OCR、ASR、视频抽帧、音频提取、内容总结、改写笔记、转码和编辑；直接下载接口返回的背景音乐属于范围内。
