# Spec：单条动态完整归档与跨平台终端体验

状态：截至 2026-10-23，动态归档、绿系双主题、自适应、原生光标、平台图标、Windows 单 EXE、对称控件及图片 Logo／文字回退均已实现。本文维护当前产品要求，实际平台检查与未验收项见[验证记录](validation.md)，旧版结果不能代替新增功能验收。本规格扩展[初版 Spec #1](https://github.com/MuZiJin701/wechat-channels-downloader/issues/1)和已发布的 [Spec #2](https://github.com/MuZiJin701/wechat-channels-downloader/issues/2)；用户文档与首版 Release 整理不改变既有登录、归档与安全行为。

## 2026-10-22—23 已确认修订

- Windows 仅提供一个 Console 应用入口 `wechat-channels-downloader.exe`，兼顾双击与已有终端中的直接运行。已有终端原地运行并让 shell 等待退出；双击请求独立 Windows Terminal，优先 PowerShell 7，其次 Windows PowerShell、cmd，缺失或移交失败时回退系统控制台。嵌入 `consoleAllocationPolicy=detached` 清单，在 Windows 11 24H2（26100）及以上避免未继承控制台时的初始自动分配；更早 Windows 11 继续兼容，允许初始控制台短暂出现。恢复必要的 Python 标准流，包括 Textual 使用的双下划线版本；不隐藏或最小化用户终端，不提权、不安装软件或修改系统默认设置。仍携带 Chromium、依赖和便携数据目录。
- 普通界面及日常说明围绕微信视频号下载；检测时显示“环境检测中”，缺少或明确失效的登录态进入微信扫码，就绪后才显示输入框。网络异常不误判为失效；实际账号注册/协议确认准确标明服务对象并等待明确同意。
- 三个平台统一采用鼠尾草绿浅色与森林绿深色两套主题，取代浅紫主题。顶部品牌区右侧提供“跟随系统 / 浅色 / 深色”选择器，小窗口自动换行，支持鼠标与键盘。首次默认跟随系统，立即应用并在 `data/appearance.json` 单独原子保存模式；无效配置恢复自动模式，保存失败提示且保留本次主题，不影响登录态。自动模式约每两秒读取运行所在机器的操作系统明暗，运行中响应变化，识别失败回退浅色；手动模式保持指定主题。Windows 读取应用偏好、macOS 读取系统外观、Ubuntu/GNOME 读取桌面颜色偏好，SSH 不读取客户端系统。
- 用 Logo、统一对齐、留白、主操作与真实阶段反馈突出当前任务；窗口放大时内容展开，缩小时减少留白、重排操作，高度不足时滚动，主要操作可达。Logo 复用渐变原图，品牌区分隔及少量装饰可用静态渐变和现有依赖支持的轻量反馈，正文与输入区保持纯色。成功、警告和错误保留语义颜色及文字，不增加开场等待、虚假百分比或全局终端配置变更。字体保持原样，二维码静态黑白，过小窗口明确提示；尊重 `NO_COLOR` 与宿主色彩能力。
- 提供下载、失败重试、打开下载目录和退出按钮，显示常用组合键：输入框 Enter、Ctrl+R、Ctrl+O、Ctrl+Q。按钮与顶部外观选择框使用四边完整、左右对称的细线矩形，保留纯色底、主次操作区分、悬停、键盘焦点及禁用反馈，适配浅深主题和小窗口。Tab / Shift+Tab 切换焦点，Enter / 空格确认按钮；不使用 F 区按键，下载中禁用重复提交。
- 输入框占位提示为“粘贴视频号分享链接”，不含示例网址，不主动将输入值或提示做成超链接。点击用于聚焦和定位光标，拖动选择；Ctrl+A 全选，支持 Home / End、方向键、Shift 选区、退格、删除及复制剪切粘贴。聚焦且插入点可见时使用终端原生细竖线闪烁光标；失焦、被遮挡或裁剪时隐藏，正常退出恢复终端配置的默认光标形状。长链接及中文编辑、滚动和窗口缩放不得使光标错位；系统剪贴板、光标实际形态及 URL 宿主链接识别仍需目标终端另行验收。
- 程序图标保留现有 Pillow 绘制的高清 PNG、Windows ICO、macOS ICNS；TUI 品牌区在当前终端确认图片协议及像素格尺寸后显示同一原图，保持比例、缩小到旁边三行文字的高度附近并垂直居中，取代字符或半格图形。已有 Pillow 编码 Sixel 与 kitty 图片，启动探测在 Textual 接管输入前进行并恢复终端模式，不将协议响应输入到链接框；图片按可见单元格裁剪，遵守控件遮挡并在重绘或退出时清理。无法可靠确认支持、图标不可用、`NO_COLOR`、终端复用器环境或窗口过矮时，收起图形及占位，仅保留自然左对齐的紧凑标题和说明。三平台采用同一能力原则，不要求用户更换或安装终端；当前 macOS 双击打开系统 Terminal，采用文字版，Linux 取决于桌面选择的终端，不能据平台名称承诺图片可用。控件不放 Logo。Windows 单 EXE 嵌入图标，Ubuntu `.desktop` 引用图标，首次运行或移动目录后刷新自身入口的绝对图标路径；macOS 使用带图标的 `.app` 终端启动器。保留命令行入口，主题切换不打断登录、扫码或下载，不清空输入和结果。
- 只保留最近一次结果，显示状态及保存位置，失败详情按需展开。全部完成后清空并聚焦输入框，失败或部分完成保留链接；继续保留原有正常中断保护。
- 底部常驻文本链接 `GitHub · MuZiJin701/wechat-channels-downloader ↗`，点击或 Tab / Shift+Tab 聚焦后 Enter 打开，保留浏览器打开失败反馈；移除独立 GitHub 按钮、Ctrl+G 与 Star 提示。新归档使用 `parse.json` 和 `feed.json`，页面称“解析原始数据”和“动态原始数据”，媒体使用用途名称；响应内容不改写，旧归档不迁移。

## Problem Statement（需求提出时）

需求提出时，程序已能输入视频号分享链接并下载视频或图文，但当时输出只包含主视频或图文图片以及 TXT 正文。独立封面、头像、认证图标、背景音乐、其他视频版本及发布信息没有完整保存；随机目录和通用文件名不便识别内容。当前实现已按下列规格扩展，不能将本节的历史问题当作现状。

当时任一媒体下载失败会清理本次临时目录。用户因此要求明确区分完整归档、部分归档、失败和主动中断，保留已取得的内容并保护以前下载好的文件。

用户还希望在 Windows、Linux、macOS 上通过终端运行和图形界面双击使用同一 TUI：Windows 双击直接优先使用 Windows Terminal 和 PowerShell 7，采用独立主题；便携包只提供必要使用文档，启动入口使用英文名称。

## Solution

对分享链接对应的一条视频号动态，沿用本机元宝登录态解析链路，保存两步解析的完整响应，并下载接口明确提供的全部已知媒体资源：视频、图文图片、封面、作者头像、认证图标和背景音乐。不同视频版本全部保存，完全相同的地址只下载一次。保持媒体实际格式和图文顺序，不转码或生成识别笔记。

每次下载创建一个动态归档：使用作者和正文摘要命名的目录、独立媒体、一份可双击查看的离线 HTML 和两份完整 JSON。HTML 保留原正文，整理作者、时间、互动展示数量及可理解的发布信息，并引用本地图片、视频和音乐；不生成 TXT。

部分资源失败后继续处理其他资源，保留成功文件和已取得的信息，在界面及 HTML 中如实报告结果。再次下载建立新目录，不覆盖旧归档。

已有终端通过控制台入口复用当前终端；图形界面双击时打开终端并进入 TUI。Windows 优先 Windows Terminal 和 PowerShell 7，不可用时按上述规则回退。主界面使用统一独立主题，二维码区域保持黑白。分发包顶层只保留 README.md 和 README.en.md 两份使用文档，许可声明置于内部目录。

沿用已确定的平台目标：Windows 11 x64、Ubuntu 24.04 x64、macOS 14+ Intel 与 Apple Silicon。保留现有元宝登录态复用、必要时扫码、随包 Chromium 和便携数据位置约定。

## User Stories

1. 作为下载用户，我希望输入一条视频号分享链接，以便归档该链接对应的一条动态。
2. 作为视频型动态下载用户，我希望下载接口提供的视频文件，以便离线观看。
3. 作为视频型动态下载用户，我希望保存接口返回的所有不同视频版本，以便完整保留可取得的版本。
4. 作为视频型动态下载用户，我希望不同版本名称标明编码，以便选择播放器兼容的版本。
5. 作为下载用户，我希望完全相同的地址只下载一次，以便避免重复传输和占用空间。
6. 作为图文动态下载用户，我希望保存全部正文图片，以便不遗漏内容。
7. 作为图文动态下载用户，我希望保留图片顺序，以便按原有次序阅读。
8. 作为下载用户，我希望媒体保持实际返回格式，以便保留下载内容。
9. 作为下载用户，我希望独立封面一并保存，以便保留动态展示信息。
10. 作为下载用户，我希望作者头像一并保存，以便离线识别发布者。
11. 作为下载用户，我希望非空的作者认证图标一并保存，以便保留接口提供的作者展示信息。
12. 作为下载用户，我希望背景音乐有独立地址时能够下载，以便保留动态的音频资源。
13. 作为下载用户，我希望接口没有提供的可选项目自然省略，以便正常归档缺少头像、音乐或封面的动态。
14. 作为阅读用户，我希望正文原样保留，以便避免整理过程改写原意。
15. 作为阅读用户，我希望正文为空时仍可查看已有媒体，以便阅读纯媒体动态。

## Implementation Decisions

- 基于现有 Python 3.11、uv 锁定环境、Textual TUI、Playwright/Chromium 和 HTTP 下载流程实现，复用已有模块与依赖；没有新增技术栈或登录系统的需求。
- 元宝登录态检查、扫码、身份确认、有效状态复用及网络失败不误删旧状态的行为继续适用。本机先解析分享链接，再取得视频号动态信息，不要求远程解析服务。
- 在现有会话与下载编排中分别保留两步完整响应，从全部已知媒体字段收集候选资源。两步独有信息均需保留；缺失的可选字段自然省略，未知字段不进行猜测性解释。
- 视频型动态与图文动态均需完整处理。下载不同视频编码或版本、全部图文图片、独立封面、作者头像、认证图标和背景音乐，完全相同的地址只传输和保存一次，并让归档中的相关展示引用同一有效文件。
- 媒体保持实际响应格式，不通过扩展名猜测内容，不转码。验证目标地址、重定向、媒体类型和完整性；对样本中 HTTP 音乐地址可核验同地址 HTTPS，不能把已有安全校验整体放宽为任意域名或明文请求。
- 扩展现有下载结果与 TUI 状态的表达，能够区分保存位置、已完成资源及失败或中断结果；不把部分完成、失败或中断显示为全部成功。内部数据结构不在本规格中预设。
- 在归档输出中生成离线展示页，展示正文、作者、可取得的时间和互动信息以及本地媒体。正文只作安全展示处理，不改写；正文摘要仅为从原文截取的短文本。时间转换注明时区，互动展示字符串按原值保留。
- 两份 JSON 保存各步返回的完整字段，不附加请求 Cookie 或登录凭据。含时效参数的原始响应只保存在本地，不输出到公共日志、公共仓库或分发产物；展示页不依赖这些远端地址。
- 媒体、JSON 和展示页形成同一条动态归档；不再生成 TXT。外部文本、字段名和地址不得成为可执行脚本、目录穿越或任意文件写入来源。
- 下载目录采用作者与正文摘要，媒体沿用此前缀并附用途、序号或编码。缺作者时省略，缺正文时回退分享标识，清理非法字符及截短过长名称；保留全文，避免名称清理导致覆盖。
- 每次运行创建新归档目录，名称冲突附加序号，不合并、覆盖、删除或迁移旧归档。正常完成的文件与未完成内容应可区分，不因某项失败删除其他已完成文件。
- 继续处理单项失败后剩余的资源。全部计划资源及归档信息保存成功时报告完成；部分资源失败时保留成果并报告部分完成、在展示页列明失败项；全部媒体失败时保留已取得的信息并报告失败；正常中断时保留已完成文件和可保存的信息、标记已中断。保存本身不可执行时明确报错，不承诺已保存。
- 启动入口和打包逻辑继续按平台分别处理。终端直接运行复用当前终端；Windows 双击优先 Windows Terminal，缺失时回退系统控制台，不安装终端、不修改系统默认设置。两种入口进入同一个 TUI，实际程序和英文命名入口分别适配各平台。
- macOS 使用 `.app` 终端启动器，Ubuntu 桌面使用 `.desktop` 入口，两者均带程序图标；允许系统首次信任、允许启动或控制终端提示。macOS 启动器与控制台程序、浏览器共处同一便携目录，数据保存在 `.app` 外侧，不能只移动启动器。支持目标仍为 Windows 11 x64、Ubuntu 24.04 x64、macOS 14+ 的 Intel 与 Apple Silicon，不以单个平台构建推断其他平台可用。
- 界面使用独立主题，字体保持终端设置，保持交互和错误可辨识；二维码区域继续黑白显示。退出后在浏览器子进程清理完成时恢复原终端属性。
- 沿用便携存储决策：登录态和下载内容分开保存在程序旁，macOS 应用包场景存于包外侧，位置不随工作目录变化。不可写时明确报错，不静默迁移到系统用户目录。
- 调整分发内容，只在顶层提供中英文两份 README 使用文档；第三方许可及声明放内部目录，开发文档和代理约定不随包分发。同步中英文说明及链接，保留 Chromium、应用依赖和必要许可。
- 不预建新的模块层级、下载选项系统、通用归档框架或跨账户能力；保持现有完整用户流程和模块边界，按本需求调整会话下载、归档输出、TUI 状态、启动入口和打包职责。

## Testing Decisions

- 测试边界沿用用户已明确确认的一个最高业务边界：从 TUI 的登录态检查或扫码提示、链接输入，到两步解析、资源保存、离线展示及可见结果。用户已对包含这些验证要求的整体规格确认，本次不新增访谈或下沉为大量内部函数测试。
- 覆盖现有 TUI 编排、真实 Playwright/Chromium、元宝登录态持久化、解析和下载、归档生成；仅模拟元宝、视频号与媒体等外部服务，使用临时目录，隔离外网，不加载真实凭据。
- 好的测试观察用户可见状态、实际保存的文件内容、资源顺序、目录命名、两份响应和 HTML 的本地引用；不固定内部调用次数、私有状态、辅助函数名称或未来的模块拆分。
- 既有 TUI 工作流测试已经通过键盘提交链接，验证视频、图文、扫码复用、网络与认证错误、无正文及失败保护；在同一入口扩展全部媒体类别、多个视频版本、相同地址复用、两步独有字段和缺失字段，不重新建立解析器单测体系。
- 从完整用户流程验证命名回退、中文和非法字符、超长名称、名称冲突及重复下载，断言以前归档和登录态没有被覆盖。
- 从同一流程模拟单项失败、全部失败、返回非媒体、短文件、不可写目录和正常中断；断言成功内容保留、不完整文件不被当作有效媒体、其余资源继续处理，以及状态和展示页中的失败项准确。
- 对由 TUI 实际生成的 HTML 使用现有浏览器能力检查原文和本地媒体引用、失败展示及外部文本的安全处理，并阻断非预期远端请求。格式检查不等同于真实媒体解码或离线播放验收。
- 沿用已有构建命令保护与实际产物离线 smoke 检查，检查双 README、内部许可、开发文档缺席、英文启动入口，以及产物不含个人登录态和动态归档。
- Windows 验证窗口入口、独立 Windows Terminal、shell 优先及回退、已有终端直接运行；macOS/Ubuntu 验证对应双击入口和终端运行。检查独立主题、布局、按钮及快捷键、可展开失败详情、新归档名称和旧归档保留。主题视觉、二维码可读性、零闪窗和真实文件管理器双击需要目标桌面环境的验收，不能只靠源码或模拟断言宣称通过。
- 主题检查覆盖三种模式、保存及重启恢复、系统偏好变化与不可识别回退、损坏配置及保存失败反馈、下载期间切换保护。布局覆盖大小及矮窗口与连续 resize，验证普通输入、中文/长链接光标位置和焦点；真实终端离线 smoke 覆盖主题选择、编辑和原生光标启用/退出恢复序列。检查资源格式与打包图标；macOS 构建检查启动器 shell 与 AppleScript 语法，实际 Finder/Terminal 仍需人工验收。
- Linux/macOS 继续复用现有源码入口与打包产物的真实 PTY 检查，验证 Chromium 启动、正常退出和原终端属性恢复；Windows 明确跳过 POSIX 专属检查，不将跳过记录为平台通过。
- 实现阶段运行项目类型检查、完整测试和构建/产物检查。本轮按用户要求仅验证 Windows 本机，不运行 Linux/macOS 构建或触发 CI；后续跨平台检查沿用现有 CI 架构。记录实际系统版本、架构及跳过项，历史结果不覆盖本轮变更，较新 Intel macOS 的通过不能替代最低目标版本。
- 人工验收单独覆盖真实扫码与复用、至少一条视频型动态和一条图文动态、可取得的附属资源完整下载、离线播放以及两种启动方式。既有测试结果和资源首部读取不作为本规格的新验收结果。

## Out of Scope

- 发布者账号全量历史、批量队列、直播录制、非视频号站点和任意小程序链接。
- 接口未返回且本链路未证实能取得的评论正文、评论或点赞者名单、独立字幕、上传前原片、完整位置数据和创作者后台数据。
- OCR、ASR、视频抽帧、音频提取、内容总结、改写笔记、转码和编辑；直接下载接口返回的背景音乐属于范围内。
- 旧归档迁移、自动清理、覆盖合并、断点续传、多账户、云端同步、自动更新或托管解析服务。
- 自动安装 Windows Terminal、修改系统默认终端、自动绕过安全验证，以及承诺所有 Linux 桌面环境或未实测系统版本均可用。
- 收费分发方案和许可谈判；已有第三方许可保留要求继续适用。
